# Правила работы с сайтом TOHARO LAB

Инструкция для агента (Ива). Читается перед любым изменением в проекте.

Три документа, и у каждого своя роль:

- **этот файл** — что можно и чего нельзя менять, как публиковать, как проверять;
- **[docs/editorial.md](docs/editorial.md)** — как писать текст, чтобы его цитировал AI-поиск;
- **[docs/content-plan.md](docs/content-plan.md)** — о чём писать и в каком порядке.

---

## Что это за сайт

Статический блог. Никакой админки, API, базы данных и авторизации не существует — и не должно появиться. На проде лежат только HTML, CSS и картинки, которые отдаёт nginx. Единственный способ что-то изменить — коммит в репозиторий.

**Репозиторий публичный.** Всё, что попадает в коммит, видит любой человек в интернете.

## Железные правила

Нарушение любого из них ломает либо безопасность, либо сборку.

### 1. Никаких секретов в репозитории

Ключи, токены, пароли, `.env`-файлы — никогда. Утёкший ключ считается скомпрометированным сразу: удалить коммит недостаточно, ключ придётся отзывать.

Ключи живут в `.env.local` (он в `.gitignore`) или в переменных окружения. В коде читаются через `process.env.ИМЯ`.

Проверка стоит на pre-commit хуке и блокирует коммит. Обходить `--no-verify` нельзя.

### 2. Не добавлять серверный код

Сборка статическая (`output: "export"`). Сломают её и вернут поверхность атаки:

- `route.ts` — серверные API-маршруты
- `proxy.ts` / `middleware.ts`
- Server Actions, формы с отправкой данных
- `export const dynamic = "force-dynamic"`
- обращения к внешним API из кода страниц

Нужно что-то посчитать или получить — делайте это **на этапе сборки** (как `src/lib/posts.ts` читает файлы с диска) или **скриптом в `scripts/`**, результат кладите в файл. В браузере пользователя не должно выполняться ничего, кроме навигации.

### 3. Slug поста неизменен

Имя файла = URL. На него ссылаются другие статьи, его запомнил поиск. Переименование = битые ссылки и потеря позиций.

Нужен другой адрес — это новый пост, а старый удаляется осознанно.

### 4. Всё проверяется перед пушем

```bash
npm run check
```

### 5. Ничего не выдумывать в текстах

Версии, цифры, названия, поведение инструментов — только проверенное. Не уверены — проверьте в первоисточнике или не пишите. Одна выдуманная деталь обесценивает весь блог.

## Публикация поста

```bash
# 1. Заготовка (создаётся черновиком)
npm run new-post -- --title "Заголовок" --category Гайд --excerpt "Описание" --read-time "9 МИН ЧТЕНИЯ"

# 2. Написать текст в созданный файл по правилам docs/editorial.md

# 3. Обложка
npm run cover -- --slug my-post --prompt "minimalist editorial illustration, warm cream background, lime green accent, flat vector, no text" --alt "Описание картинки по-русски"

# 4. Опубликовать
npm run post -- publish my-post

# 5. Проверить и отправить
npm run check
git add -A && git commit -m "post: заголовок" && git push
```

Дальше VPS подхватит изменения и пересоберёт сайт.

**Черновики безопасны.** Пост с `published: false` не попадает в сборку вообще — ни страницы, ни заголовка в HTML. Незаконченное можно спокойно коммитить.

## Управление постами

```bash
npm run post -- list                      # все посты со статусами
npm run post -- show <slug>               # frontmatter и начало текста
npm run post -- set <slug> --title "…"    # поправить поля
npm run post -- rewrite <slug> --file f   # заменить текст целиком
npm run post -- unpublish <slug>          # снять с сайта, файл остаётся
npm run post -- delete <slug> --yes       # удалить пост и обложку
```

`set`, `rewrite` и `publish` сами проставляют дату обновления.

Перед `delete` подумайте про `unpublish`: удаление необратимо, а ссылка станет 404.

## Формат frontmatter

```yaml
---
title: 'Заголовок'
excerpt: 'Сжатый ответ в 1–3 предложения, до 320 знаков'
category: 'Гайд'          # Статья | Гайд | Заметка
readTime: '9 МИН ЧТЕНИЯ'
cover: '/covers/my-post.jpg'
coverAlt: 'Описание картинки по-русски'
date: '2026-08-10'
updated: '2026-09-01'      # проставляется автоматически
tags: ['claude code', 'агенты']
published: true            # true/false без кавычек
---
```

Что проверяется автоматически и роняет сборку:

| Правило | Почему |
| --- | --- |
| `category` — ровно из списка | Иначе рубрика не отобразится |
| `published` — булево без кавычек | Строка `"false"` истинна, черновик уедет на сайт |
| `date`, `updated` — `ГГГГ-ММ-ДД` | Идут в sitemap и JSON-LD |
| `excerpt` до 320 знаков | Это описание для поиска |
| Имя файла — латиница, цифры, дефисы | Это URL |
| Заголовки не дублируются | Поисковики считают это каннибализацией |
| `<Partner id>` есть в `content/links.json` | Иначе ссылка ведёт в никуда |
| Партнёрская ссылка → есть `<Disclosure />` | Требование честности перед читателем |
| `cover` указывает на существующий файл | Иначе битая картинка |

Предупреждения (не блокируют, но исправьте): нет обложки, нет `coverAlt`, текст короче нормы, нет подзаголовков, осиротевшая обложка от удалённого поста.

## Компоненты внутри текста

```mdx
<Answer>Прямой ответ на вопрос заголовка, 2–4 предложения.</Answer>

<Note title="Осторожно">Замечание по ходу текста.</Note>

<Partner id="cursor">Cursor</Partner>      <!-- ссылка из content/links.json -->

<Disclosure />                              <!-- раскрытие партнёрства -->

<Post slug="drugoy-post">текст ссылки</Post>  <!-- ссылка на свой материал -->
```

Обычный Markdown работает как есть.

## Изменения в самом сайте

Иногда нужно не написать пост, а поменять сайт: добавить раздел, блок, страницу. Порядок такой.

### Новая рубрика

1. `src/lib/post-schema.ts` — добавить в `CATEGORIES`, `CATEGORY_SLUGS`, `CATEGORY_TITLES`
2. `scripts/check-posts.mjs` и `scripts/post.mjs` — добавить в массив `CATEGORIES` (там свои копии, они намеренно независимы от TypeScript)
3. `scripts/check-posts.mjs` — задать порог объёма в `MIN_BODY_CHARS`
4. `src/components/site-header.tsx` — добавить в `NAV`
5. `src/components/site-footer.tsx` — добавить в список разделов
6. Собрать и проверить, что `/category/<slug>/` открывается

Просто написать новое значение в frontmatter недостаточно — проверка не пропустит.

### Новая страница

Создать `src/app/<путь>/page.tsx`. Обязательно:

- экспортировать `metadata` с `title` и `description`;
- добавить ссылку в шапку или подвал, иначе страницу никто не найдёт;
- добавить в `src/app/sitemap.ts`;
- никаких `"use client"` без необходимости и никаких серверных вызовов.

### Новый блок на странице

Компоненты живут в `src/components/`. Правила:

- по умолчанию серверный компонент; `"use client"` — только если нужны состояние или обработчики (как в `mobile-nav.tsx`);
- стили — только токенами из `globals.css` (`bg-bg`, `text-ink`, `border-line`, `bg-accent`), новые цвета не выдумывать;
- шрифты: `font-display` в заголовках, `font-mono` в метках и подписях, `font-serif` в тексте статей;
- картинки — только через `<CoverImage>`, чтобы проставились размеры и не прыгала вёрстка.

### Новый формат изображений

Появился блок с другими пропорциями — добавьте формат в `IMAGE_FORMATS` (`src/lib/images.ts`) и в `FORMATS` в `scripts/make-cover.mjs`. Картинку генерируйте сразу в нужных пропорциях: если сгенерировать квадрат и вставить в широкий блок, браузер обрежет края и с картинки уедет центр композиции.

### Чего не делать без спроса

- Менять палитру, шрифты, логотип и общий вид — это айдентика, она утверждена
- Добавлять зависимости, если задача решается тем, что уже есть
- Подключать внешние скрипты, счётчики, шрифты с CDN — CSP их заблокирует, и это сделано намеренно
- Трогать `deploy/` без явной просьбы — от этих файлов зависит работающий прод
- Переписывать чужие посты целиком без запроса

## Статистика

Смотреть на `https://toharo.space/stats/` (по паролю). Считается по логам nginx, без счётчиков и JS.

Что видно: просмотры каждой статьи, источники переходов, клики по партнёрским ссылкам (`/go/<id>/`), битые ссылки, и читают ли сайт краулеры AI-поиска (`GPTBot`, `ClaudeBot`, `PerplexityBot`).

Настройка — в [deploy/stats.md](deploy/stats.md).

## Проверка перед пушем

```bash
npm run check     # посты + секреты
npm run build     # сборка целиком
npm run lint
```

Если меняли вёрстку — запустите `npm run dev` и посмотрите глазами на 375px и на десктопе.
