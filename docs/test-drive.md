# Прогон: как мы тестируем инструменты

Регламент для Ивы. По нему из хайпового репозитория получается материал, который нельзя написать, не запустив инструмент.

Смысл всего документа в одной фразе: **мы публикуем не мнение, а результат замера**. Мнение есть у всех и стоит ноль. Замер — то, чего нет больше нигде, и именно его цитируют.

---

## Из чего состоит прогон

```
кандидат → отбор → песочница → базовый прогон → прогон с инструментом
        → сравнение → статья + сценарий видео
```

Пять из семи шагов Ива делает сама. Согласование кандидата и запись видео — за владельцем.

---

## Шаг 1. Кандидаты

Ищем то, что **можно проверить за вечер и что решает понятную задачу**.

Где смотреть:

- GitHub Trending за неделю, языки: TypeScript, Python, Shell;
- новые репозитории с быстрым ростом звёзд (не абсолютное число, а прирост за 7 дней);
- релизы инструментов, которыми мы пользуемся: Claude Code, Codex, Antigravity, Cursor;
- каталоги: skills.sh, реестры MCP-серверов;
- то, о чём вторую неделю спрашивают в чатах.

Ива готовит список из 5–7 кандидатов и присылает владельцу в таком виде:

```
1. <название> — <ссылка>
   Что обещает: одна фраза
   Звёзд: N (+M за неделю)
   Как проверим: конкретная задача, на которой будет видно разницу
   Против чего сравним: базовый способ без этого инструмента
   Сколько займёт: оценка в часах
   Риск: чем может оказаться пустышкой
```

Владелец отвечает «берём номер такой-то». **Без согласия прогон не начинается** — время дорогое, а половина хайпа не стоит вечера.

## Шаг 2. Отбор

Кандидат проходит, если выполняются все четыре условия:

- **проверяемо** — есть задача, где разница будет видна в цифрах или на скриншоте;
- **воспроизводимо** — читатель сможет повторить у себя;
- **укладывается в вечер** — до 4 часов вместе с записью;
- **есть с чем сравнить** — понятно, как делали до.

Не проходит: инструменты с закрытой бетой без доступа, всё, что требует платной подписки дороже 20 долларов ради одного теста, обёртки без собственной ценности.

---

## Шаг 3. Песочница

**Жёсткое правило: чужой код с GitHub запускается только в изолированной среде.**

Хайповый репозиторий — это произвольный код, который мы выполняем у себя. Постскрипты установки, `curl | bash` в инструкции, зависимости из непроверенных источников. Один такой прогон на рабочей машине — и утекут ключи и доступы.

Требования к песочнице:

- отдельная виртуалка или контейнер, не рабочая машина и не сервер, где живёт Ива;
- никаких боевых ключей: только временные, с минимальными правами, отзываемые после теста;
- нет доступа к репозиториям владельца и к продакшену;
- после прогона среда уничтожается целиком, а не «чистится».

Песочница развёрнута на VPS рядом с Ивой: [deploy/sandbox/](../deploy/sandbox/). Разово ставится `install.sh`, дальше на каждый прогон:

```bash
./sandbox.sh start <имя>     # чистый контейнер
./sandbox.sh shell <имя>     # войти и работать
./sandbox.sh collect <имя>   # забрать артефакты
./sandbox.sh destroy <имя>   # уничтожить целиком
```

Контейнер не видит `/root/iva`, ключи и репозитории владельца, не достучится до сервисов на localhost VPS и ограничен по памяти и процессам. Артефакты выносятся только через `/work/out`.

**Что проверить до запуска:** дату последнего коммита, число контрибьюторов, есть ли в скриптах установки обращения к незнакомым доменам. Если репозиторий появился вчера и весь код написан одним аккаунтом без истории — это повод не запускать вовсе, а не просто изолировать.

## Шаг 4. Базовый прогон

Сначала делаем задачу **без** тестируемого инструмента. Это и есть «было», без него сравнивать не с чем.

Фиксируем заранее и не меняем потом:

| Что фиксируем | Зачем |
| --- | --- |
| Формулировка задачи | Одна и та же в обоих прогонах, слово в слово |
| Модель и её версия | Иначе сравниваем модели, а не инструменты |
| Стартовое состояние | Пустая папка или конкретный коммит репозитория |
| Критерий готовности | Что считаем успехом: тесты зелёные, страница открывается, файл создан |

Замеряем:

- **время** от старта до готового результата;
- **стоимость**: токены или деньги;
- **число итераций** — сколько раз пришлось поправлять;
- **дефекты** в результате;
- **артефакты**: файлы, скриншоты, логи — складываем в папку прогона.

## Шаг 5. Прогон с инструментом

То же самое, но с тестируемым инструментом. **Меняется ровно одна переменная.**

Частая ошибка: заодно поменять модель, переформулировать задачу «поудачнее» или дать больше подсказок. После этого сравнение бессмысленно, а материал — враньё с цифрами.

Отдельно записываем то, чего в цифрах не видно: где инструмент сломался, что пришлось обойти, что в документации написано неверно. **Это самая ценная часть материала** — её нет ни в README, ни у конкурентов.

## Шаг 6. Сравнение

Сводим в таблицу. Она пойдёт в статью как есть:

| | Без инструмента | С инструментом |
| --- | --- | --- |
| Время | | |
| Стоимость | | |
| Итераций | | |
| Дефектов в результате | | |
| Результат | | |

Правила честности:

- **Прогон один раз ничего не доказывает.** Модели недетерминированы: три прогона на каждой стороне, в таблицу идёт медиана, разброс упоминается в тексте.
- **Отрицательный результат — тоже результат.** «Не дал выигрыша» публикуем так же охотно. Такие материалы читают внимательнее всего, потому что их почти никто не пишет.
- **Не подгонять задачу под инструмент.** Если задачу выбрали так, чтобы инструмент точно выиграл, это реклама, а не прогон.
- **Указывать границы.** «Проверено на проекте из 30 файлов, как поведёт себя на 3000 — не знаю» честнее, чем молчание.

## Шаг 7. Что получается на выходе

Из одного прогона выходит три разных материала, и они не дублируют друг друга:

**Telegram** — короткий итог в день окончания: что тестировали, одна цифра, ссылка на статью, когда выйдет.

**Статья на сайт** — по правилам [editorial.md](editorial.md): ответ в начале, таблица сравнения, раздел «где сломалось», раздел «кому не подойдёт». Рубрика — «Статья», если разбираем как устроено, «Гайд», если получилась пошаговая инструкция.

**Сценарий видео** — если решили записывать.

---

## Сценарий видео

Ива готовит сценарий **после** прогона, по реальным данным. Никаких «предположим, получится».

Структура на 8–12 минут:

```
0:00  Крючок: результат сразу. «Собрал лендинг за 6 минут вместо 40. Показываю как»
0:20  Что тестируем и против чего
0:40  Установка — быстро, подробности в описании
1:30  Базовый прогон: делаем задачу обычным способом
4:00  Прогон с инструментом: та же задача
7:00  Сравнение: таблица на экране
8:30  Где сломалось и кому не подойдёт
9:30  Итог и ссылка на статью
```

Файл сценария кладётся в папку прогона в таком формате:

```markdown
## Блок 3. Установка
**Экран:** терминал, чистая папка
**Действие:** npm install <пакет>
**Говорим:** «Ставится одной командой, ключей не просит»
**Длительность:** 40 секунд
```

Три поля: что на экране, что делаем руками, что говорим. Текст «говорим» пишется **разговорно** — его читают вслух, а не глазами. Длинные придаточные и канцелярит вслух не звучат.

Этот же файл подхватывает суфлёр в студии.

## Папка прогона

Каждый прогон живёт отдельной папкой и не смешивается с другими:

```
runs/2026-08-15-<инструмент>/
  plan.md          согласованный план: задача, критерии, что с чем сравниваем
  baseline/        артефакты базового прогона + лог
  with-tool/       артефакты прогона с инструментом + лог
  metrics.json     замеры обоих прогонов
  findings.md      что сломалось, что удивило, обходные пути
  script.md        сценарий видео
  article.md       черновик статьи
```

`metrics.json` — машинно-читаемые цифры, из них потом строятся графики в студии:

```json
{
  "tool": "название",
  "task": "одной фразой",
  "model": "модель и версия",
  "runs": 3,
  "baseline": { "seconds": [420, 455, 401], "cost_usd": [0.31, 0.28, 0.33], "iterations": [4, 5, 4], "defects": 2 },
  "with_tool": { "seconds": [180, 205, 176], "cost_usd": [0.12, 0.14, 0.11], "iterations": [1, 2, 1], "defects": 0 }
}
```

## Чеклист прогона

- [ ] Кандидат согласован владельцем
- [ ] Репозиторий проверен на вменяемость до запуска
- [ ] Запуск только в песочнице, боевых ключей рядом нет
- [ ] Задача, модель и критерий готовности зафиксированы до старта
- [ ] Оба прогона по три раза
- [ ] Между прогонами изменилась ровно одна переменная
- [ ] Артефакты и логи сохранены
- [ ] `metrics.json` заполнен
- [ ] В `findings.md` есть хотя бы одна вещь, которой нет в документации
- [ ] В статье есть раздел «кому не подойдёт»
- [ ] Песочница уничтожена, временные ключи отозваны
