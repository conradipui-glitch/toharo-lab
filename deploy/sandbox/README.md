# Песочница для прогонов

Изолированная среда на VPS, в которой тестируются чужие репозитории.

## Зачем она нужна

Хайповый репозиторий с GitHub — это **произвольный код, который вы соглашаетесь выполнить**. В инструкциях по установке регулярно встречается `curl | bash`, в зависимостях — постскрипты, которые запускаются при `npm install` ещё до того, как вы что-то вызвали.

На машине, где лежат ключи и доступы к боевым системам, такое запускать нельзя. Один неудачный прогон — и утекает всё, до чего дотянется процесс.

Отсюда правило из [регламента](../../docs/test-drive.md): **прогон идёт только в одноразовой изолированной среде, и после него среда уничтожается целиком.**

## Что здесь лежит

| Файл | Что делает |
| --- | --- |
| `install.sh` | Ставит Docker на VPS, разово |
| `Dockerfile` | Образ песочницы: Node, Python, git и ничего лишнего |
| `sandbox.sh` | Запуск, вход, сбор артефактов, уничтожение |

## Установка на VPS

Разово, от root:

```bash
cd /srv
git clone https://github.com/conradipui-glitch/toharo-lab.git
cd toharo-lab/deploy/sandbox
chmod +x install.sh sandbox.sh
./install.sh
```

Скрипт ставит Docker из официального репозитория и проверяет, что он поднялся.

## Как пользоваться

```bash
# Собрать образ (разово и после правок Dockerfile)
./sandbox.sh build

# Новый прогон: создаёт чистый контейнер
./sandbox.sh start my-run

# Войти внутрь и работать
./sandbox.sh shell my-run

# Забрать артефакты наружу, в runs/<имя>/
./sandbox.sh collect my-run

# Уничтожить: контейнер и всё, что в нём осталось
./sandbox.sh destroy my-run
```

Внутри контейнера рабочая папка — `/work`. Всё, что нужно вынести наружу, кладите в `/work/out`.

## Что именно изолировано

| Ограничение | Зачем |
| --- | --- |
| Отдельная файловая система | Код прогона не видит `/root/iva`, ключи и репозитории |
| Пользователь без root | Даже внутри контейнера код не всесилен |
| Нет доступа к сети хоста | Контейнер не достучится до сервисов на localhost VPS |
| Ограничение памяти и процессов | Зависший прогон не уронит сервер |
| Нет переменных окружения хоста | Ключи Ивы в контейнер не попадают |
| Контейнер удаляется целиком | «Почистить» недостаточно, удаляется всё |

## Чего это НЕ даёт

Контейнер — не полная виртуальная машина. От целенаправленного побега он защищает хуже, чем отдельный сервер.

Поэтому дополнительно:

- **Не передавайте в песочницу боевые ключи.** Нужен ключ для теста — выпустите временный с минимальными правами и отзовите после.
- **Проверяйте репозиторий до запуска.** Дата последнего коммита, число контрибьюторов, обращения к незнакомым доменам в скриптах установки. Репозиторий, появившийся вчера и написанный одним аккаунтом без истории, — повод не запускать вовсе.
- **Не монтируйте папки хоста на запись**, кроме `out`.

## Если Docker ставить не хочется

Альтернатива — отдельный дешёвый VPS под прогоны, который не жалко пересоздать. Изоляция лучше, но каждый прогон стоит денег и времени на разворачивание. Для регулярных прогонов контейнер практичнее.
