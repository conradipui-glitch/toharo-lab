# research — система развития сайта на поисковом спросе

Здесь живёт исследовательская часть TOHARO LAB: что ищут люди, что у сайта уже есть и что делать дальше. История не перезаписывается — каждый замер хранится со своей датой.

## Структура

| Путь | Что это |
| --- | --- |
| `content-map.md` | Живая карта контента: посты, рубрики, теги, перелинковка, покрытие направлений |
| `audits/ГГГГ-ММ-ДД.md` | Аудит сайта на дату. Новый аудит — новый файл, старые не редактируются |
| `snapshots/` | Датированные замеры спроса (Wordstat через инструмент yaai) |
| `topics/` | Разборы по тематическим направлениям: seed-наборы и находки |
| `page-plan/` | Page Planner: решения по страницам — EXPAND / CREATE / MERGE / HOLD |
| `content-backlog.csv` | Редакционный backlog: приоритет, действие, тема, запросы, целевой URL |

Папки `snapshots/` и `page-plan/` заполняются с 2026-09-15 (первый прогон Wordstat, этап 2). `topics/` и `content-backlog.csv` — этап 3.

## Цикл

1. **Замер.** Пакетный прогон yaai по seed-наборам направлений. API-ключи хранятся только в GitHub Secrets репозитория `conradipui-glitch/yaai` — в файлах репозитория и на дисках их нет.
2. **Сравнение.** Новый замер сверяется с предыдущим (в yaai есть `compare-snapshots`): резкие изменения спроса — повод присмотреться.
3. **Решения.** Спрос раскладывается по страницам: усилить существующую (EXPAND), создать новую (CREATE), встроить блоком в существующую (MERGE), не трогать (HOLD).
4. **Редактура.** Темы уходят в `content-backlog.csv`; для приоритетных пишется Content Brief.
5. **Ревизия.** Старые материалы периодически пересматриваются: KEEP / EXPAND / REFRESH / MERGE / SPLIT.

Ритм: недельный прогон по направлениям; месячный — полный повтор seed-набора со сравнением снапшотов.

## Правила

- Секретов здесь нет и не будет. Ключи не попадают ни в чат, ни в логи, ни в коммиты.
- Датированные снапшоты не редактируются задним числом.
- Частотности похожих запросов не суммируются («объём рынка» из суммы — ложная точность). Количественная база — Top-запросы Wordstat; Associations — только источник формулировок.
- Отдельная страница создаётся только под устойчивый спрос. Под каждую формулировку — никогда.
- DELETE / REDIRECT существующих страниц — только при реальной проблеме, не «для порядка».
