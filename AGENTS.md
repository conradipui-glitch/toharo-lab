# Инструкция для агента (Ива)

Это статический сайт. Публикация поста = создать `.mdx` файл, закоммитить и запушить. Больше ничего.

## Как опубликовать пост

**Шаг 1.** Создать заготовку (скрипт сам сделает корректный frontmatter и slug):

```bash
npm run new-post -- --title "Заголовок поста" --category Гайд --excerpt "Описание для карточки" --read-time "8 МИН ЧТЕНИЯ"
```

Скрипт напечатает путь к созданному файлу. Пост создаётся **черновиком**.

**Шаг 2.** Написать текст в созданный файл (тело после `---`), обычный Markdown.

**Шаг 3.** Когда текст готов — поменять в frontmatter `published: false` на `published: true`.

**Шаг 4.** Проверить и запушить:

```bash
npm run check
git add content/posts/
git commit -m "post: заголовок поста"
git push
```

На VPS деплой подхватит изменения и пересоберёт сайт.

## Формат frontmatter

```yaml
---
title: 'Заголовок поста'
excerpt: 'Описание в карточке, 1–3 предложения'
category: 'Гайд'
readTime: '8 МИН ЧТЕНИЯ'
cover: ''
date: '2026-08-10'
published: true
---
```

Жёсткие правила — их проверяет `npm run check`, и сборка падает при нарушении:

| Поле | Требование |
| --- | --- |
| `category` | Ровно одно из: `Статья`, `Гайд`, `Заметка`. Другие значения не пройдут |
| `published` | `true` или `false` **без кавычек** |
| `date` | `ГГГГ-ММ-ДД` |
| `title`, `excerpt` | Непустые |
| Имя файла | Только латиница, цифры, дефисы. Имя файла = URL поста |

## Что важно понимать

**Черновики безопасны.** Пост с `published: false` не попадает в сборку вообще — ни страницы, ни заголовка в HTML. Можно спокойно коммитить незаконченное.

**Имя файла менять нельзя** после публикации — это URL, ссылки сломаются. Slug задаётся один раз при создании.

**Рубрики.** Чтобы добавить новую, надо править `CATEGORIES` и `CATEGORY_SLUGS` в `src/lib/post-schema.ts` и `CATEGORIES` в `scripts/*.mjs`. Просто написать новое значение в frontmatter недостаточно — проверка не пропустит.

**Проверяй перед пушем.** `npm run check` занимает секунду и ловит все типовые ошибки формата.

## Чего в проекте нет

Ни админки, ни API, ни базы данных, ни авторизации. Это сделано намеренно: на проде лежит только статика, поэтому взламывать нечего. Не добавляй серверные маршруты (`route.ts`), формы отправки данных или `middleware`/`proxy` — они сломают статический экспорт (`output: "export"`) и вернут поверхность атаки.

## Структура

| Путь | Что это |
| --- | --- |
| `content/posts/*.mdx` | Все посты. Единственное, что нужно трогать для публикации |
| `src/lib/post-schema.ts` | Рубрики, типы, slugify |
| `src/lib/posts.ts` | Чтение постов с диска (только сборка) |
| `src/app/` | Страницы |
| `scripts/` | `new-post` и `check` |
| `deploy/` | Скрипт деплоя и конфиг nginx для VPS |
